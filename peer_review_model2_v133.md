## Strengths

- The core seq2seq setup is technically plausible and mostly well described: a 21-day encoder, autoregressive decoder, teacher forcing during training, AdamW, ReduceLROnPlateau, Optuna search, and early stopping are all standard choices for multi-step forecasting. The report also correctly notes that once targets are standardised, the proposed "NSE+MSE" loss is effectively a scaled MSE, which is an honest clarification rather than a hidden issue (Methods 4.3, lines 544-578).
- The chronological train/validation/test split is conceptually sound, and the report explicitly states that windows do not cross split boundaries and that normalisation statistics are fit on training data only. Those are the right anti-leakage rules for time-series forecasting (Data 3.5, lines 440-462).
- The baseline family is sensible for a CAS project: persistence, climatology, and multi-horizon Ridge cover naïve, seasonal, and regularised linear baselines. The Ridge implementation as 28 separate horizon/target models on flattened lag features is methodologically reasonable (Methods 4.2, lines 528-543).
- The report is commendably transparent about limitations. In particular, it explicitly acknowledges a possible interpolation-related leakage path and does not hide the failure of river→lake transfer or the underperformance of the cascaded model (Limitations, lines 2242-2266; Results 5.7, lines 1790-1844; Discussion 6.3, lines 2168-2196).
- Using a signed-rank test across gauges, rather than treating all overlapping forecast windows as independent, is directionally the right level for cross-site inference. The idea is better than doing per-window hypothesis testing on autocorrelated residuals (Results 5.3, lines 1245-1267).

## Issues

### High priority

- **The "zero-shot" transfer protocol is not truly zero-shot as written.** The report says that each target gauge uses its own scaler fit on that gauge's training data, and that scaling includes target mean/std for the target variable (Data 3.5, lines 446-451; Methods 4.5, lines 673-683). For DO forecasting, that means the transfer model is allowed to use historical target-gauge DO labels to calibrate the output scale before evaluation. That is not weight retraining, but it is still target-domain adaptation using labeled target data. The reported transfer numbers are therefore more accurately "parameter-frozen transfer with target-gauge normalisation," not pure zero-shot transfer.
- **The NeuralHydrology EA-LSTM comparison is not apples-to-apples enough to support strong ranking claims.** Table 4 compares AareML means excluding the training gauge 2473, while Table 4b reports a NeuralHydrology mean over 12 gauges including 2473; four additional gauges are also dropped from NH because of missing static attributes (Results 5.3, lines 1208-1229; Results 5.3c, lines 1337-1488). On top of that, the report itself admits differences in training data, feature sets, and optimisation, so the sentence that this benchmark "confirms the findings" is too strong.
- **The cascaded-model interpretation is overclaimed.** The tested cascade uses a linear temperature→oxygen stage and then an LSTM residual model, but dissolved-oxygen saturation is not truly linear in temperature and also depends on pressure/altitude and other processes. A failure of this specific cascade does not establish that the direct LSTM has "implicitly learned the temperature–DO solubility relationship" in a strong scientific sense; it only shows that this particular decomposition underperformed (Discussion 6.3, lines 2168-2196).

### Medium priority

- **The final-model training protocol is not fully cleanly separated from model selection.** The best hyperparameters are chosen by Optuna on the validation period, then the report says the final model is retrained on "train+val" but with early stopping on a hold-out slice carved from validation (Results 5.2, lines 812-831). That is better than using test data, but it is still a reuse of the validation period for both tuning and stopping, and the phrase "trained on train+val" is not literally true if a validation slice is withheld for stopping.
- **The baseline story is internally inconsistent because VAR(7) appears late, performs very well, but is not part of the formal baseline section or main tables.** Methods 4.2 defines only three baselines, yet later the text reports VAR(7) at RMSE 0.299, slightly better than the direct LSTM and Ridge on the single gauge (Results 5.3, lines 1269-1275). If VAR is a real comparator, it should be specified in Methods and included systematically; if it is only a side analysis, it should not be used rhetorically to support broader claims.
- **The SHAP analysis is acceptable as approximate attribution, but the interpretation goes beyond what it can safely support.** GradientSHAP on a differentiable seq2seq model is reasonable for exploratory feature attribution, especially for the 1-day-ahead forecast only (Results 5.4, lines 1490-1499). However, using mean absolute attributions under highly correlated lagged inputs to conclude that the model's "effective memory is only 3–4 days" is too strong; low attribution on older lags does not prove those lags are irrelevant to the recurrent state.
- **Interpolation before chronological splitting is a real leakage risk, not just a theoretical footnote.** The report acknowledges that linear interpolation is applied to the full time series before splitting (Limitations, lines 2242-2266). Even if the effect is probably small at gauge 2473, this should be treated as a methodological flaw to be fixed, because boundary-spanning gaps can leak future information into earlier splits.
- **The inference language around the custom loss is stronger than the evidence supports.** Since the proposed loss collapses to scaled MSE after standardisation, statements that it improves "sequence fidelity" or materially explains better KGE are not really justified by the loss definition alone (Methods 4.3, lines 564-578; Ablation, lines 1961-1973). At most, the report shows an empirical association in one ablation table.

### Low priority

- **The block-bootstrap CI idea is broadly fine, but the implementation details are underspecified.** A 30-day temporal block bootstrap with 500 replicates is reasonable for autocorrelated test series (Methods 4.4, lines 659-661), but the report does not say whether blocks are sampled over forecast origins, over daily errors, or with what CI construction rule. That matters for overlapping multi-horizon windows.
- **There is at least one numerical inconsistency in the significance reporting.** The main multi-site section reports zero-shot LSTM vs Ridge at p = 0.037 with n = 10 (Results 5.3, lines 1245-1267), but the conclusion later states p = 0.024 for what appears to be the same comparison (Conclusion, lines 2324-2333). That weakens confidence in the statistical reporting.
- **Using a 3-seed ensemble for the main LSTM while comparing against single deterministic baselines slightly favors the neural model.** This is not fatal, but the comparison is not perfectly symmetric (Results 5.1-5.2, lines 803-805 and 833-1015).

## Suggested fixes

1. Redefine the transfer terminology. Call the current protocol something like **"frozen-weight transfer with target-gauge scaling"** rather than zero-shot, and add a stricter experiment that uses only source-gauge scaling or a global scaler learned without target DO labels.
2. Move all preprocessing steps inside the chronological split. Interpolate separately within train, validation, and test partitions so no operation can borrow information across boundaries.
3. Clean up model selection. Use one split for Optuna, a separate inner hold-out for early stopping, and reserve the reported validation period exclusively for selection; alternatively use rolling-origin validation.
4. Make the benchmark tables apples-to-apples. For NeuralHydrology, compare on the identical gauge subset, identical averaging rule, identical horizon/task definition, and clearly state whether the mean includes the source gauge.
5. Decide whether VAR(7) is a formal baseline. If yes, add it to Methods, results tables, and multisite comparisons; if no, keep it explicitly exploratory and avoid implying that the main baseline set was exhaustive.
6. Rephrase the SHAP section more conservatively. Say it provides **approximate local attribution for the 1-day-ahead forecast** and that older-lag attenuation is suggestive, not proof, of a short effective memory.
7. Rephrase the cascaded-model conclusion. The safe claim is that **this tested linear-plus-residual cascade underperformed the direct LSTM**; do not generalise that all physics-informed decompositions are unnecessary.
8. Add a short sensitivity analysis on missing-data handling: no interpolation, shorter interpolation limits, forward-fill only, and split-safe interpolation. This would materially strengthen the report.
9. Recheck all reported p-values and ensure the same gauge set is used everywhere statistical significance is cited.

## Overall score (1-10 for a CAS project)

**7/10.**

This is a strong CAS-level project in ambition, implementation effort, and breadth of experiments. The main technical weakness is not the LSTM itself, but the evaluation framing: the transfer setup uses target-gauge scaling, some benchmark comparisons are not fully like-for-like, and a few interpretations are stronger than the evidence warrants. With those points tightened, this would move much closer to an excellent methodological standard.
